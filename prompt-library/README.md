# 模型与工具测试提示词库

收录可重复使用的提示词，便于新模型或工具发布时运行同一案例、保留实际结果，并整理成 @LeoGuoLabs 的英文测试内容。

## 分类

按产出的主要用途分类，每个案例只设一个主分类；声音、图像、三维等特征作为标签。浏览器内运行的游戏仍归入游戏，具有编辑功能的网页应用归入应用与工具。

分类之外，单独标明呈现形式，例如交互式网页、可运行的桌面应用、视频或静态图。003 和 006 当前明确要求浏览器中的交互式网页；其余原始提示词尚未限定运行平台。

## 使用方法

1. 打开案例的 `prompt.txt`，将原文直接提交给待测模型或工具。案例说明和观察维度用于事后记录，不随提示词一起发送。
2. 尽量使用独立的新会话和干净工作目录，避免本项目的发布规则、历史对话或已有代码影响结果；记录实际可见的环境与设置。
3. 保存首次完整产出，再进行试玩或检查。需要追问、修复、重试或人工修改时，保留原始结果并逐条记录干预。
4. 每次测试复制 [测试记录模板](templates/run-record.md)，保存到项目的 `output/model-tests/<case-id>/<YYYYMMDD-HHMMSS>-<model-or-tool>-r01/record.md`。同一目录保留提示词快照、原始回答、代码和演示素材；时间默认使用 Asia/Singapore。
5. 比较时对齐实际提示词内容、工具权限、运行环境和测试预算；无法对齐的差异明确记录。单次演示只支持对这次结果的判断。
6. 发布时根据实测证据撰写英文内容，选用真实运行截图或录屏，并沿用项目的最终内容审核与公开验证流程。

## 新增与维护

- 在 `cases/<category>/<编号>-<short-name>/` 增加案例目录，每个目录至少包含 `README.md` 和 `prompt.txt`，并更新总索引与分类索引。编号全库连续递增，下一条从 `007` 开始，不按分类重新编号。
- 案例说明记录主分类与标签；分类调整时保留案例编号与已有运行记录，更新相关链接。运行记录仍按 `output/model-tests/<case-id>/` 保存。
- 新增或修订提示词时，在简短英文原文中明确呈现形式，例如 `interactive webpage`、`desktop app`、`video` 或 `image`；案例说明同步标注。保持主题和实现方式的开放性，不为此扩展成长篇技术要求。
- 每个案例只保留当前 `prompt.txt`，修改时直接覆盖，并同步更新案例说明与索引。提示词库不保留旧版文件、版本号或历史版本记录。
- 案例说明记录测试意图与观察点，实际结果放在各次运行记录中。未测项目写“未测试”，未知数据写“未记录”。
- 这里维护提示词与模板；实际测试、英文发布稿、媒体和发布链接集中保存在 `output/model-tests/`。
