## 只发链接时应该发生什么

默认把链接理解为“按 LeoGuoLabs 的既定要求准备一条可以发布的英文新帖”，主动完成：

1. 阅读完整原帖、媒体、引用链和必要的作者补充。
2. 找到相关原始资料，核对影响文案的关键事实和最新回应。
3. 重新理解、编排英文表达，保留有意义的观点，不逐句翻译。
4. 按媒体类型处理素材：信息图重绘、真实界面重新截图、视频找源并重新下载。
5. 在聊天里给出完整终稿、最终图片顺序、可查看的视频，以及明确的发布格式。
6. 默认只在最终发布前审核一次；同一版本已获批准，或本次明确免确认，就发布并回到真实公开页面核验。

“理解意图”落实为可靠默认值和上下文判断，不承诺从任何一个链接猜中所有未表达的想法。比如只发自己的旧帖且没有说明修改目标，仍需一个有针对性的问题；普通中文来源帖则无需再问要翻译、做图还是找视频。

## 这次解决的规则冲突

- 将“独立发布是默认”与“明确转发时使用原生转发”写成一个意图表，避免互相覆盖。
- 将“不主动加来源博主署名”与“Quote 要保留原作者”“真实证据截图要保留身份”分开，避免错误删除证据。
- 将“必须下载原视频”与“Quote 保留原生视频”分开：本地准备与发布格式是两件事。同一任务中已验证的本次下载可继续使用，无需每一轮重复下载。
- 保留发布前审核，但明确当前任务的免确认授权、已经展示完整版本后的批准，以及精确修改并发布的授权；不再机械重复确认。
- 将旧 Ego Lite 优先与后来的内置浏览器偏好统一为最新项目选择，保留明确指定浏览器的覆盖权。
- 固定最终纸感版本，不重新采用被否定的实黄背景、渐变、叶子或衬线字体。
- 平台字符上限改为历史核验信息和按需实时验证，不把旧数字写成永远成立的限制。
- 不将一次文章的特殊教程结构、一次十五分钟或十分钟的发帖间隔、一次免确认要求、其他项目的巡检频率变成所有 X 任务的默认要求。

## 自检情景

| 输入情景 | 新版规则应给出的处理 |
| --- | --- |
| 只发一个含视频的中文 X 链接 | 独立英文稿、找源、新下载完整视频、检查、提供最终审核 |
| 只发信息图帖 | 提炼内容并查证，按固定风格准备英文图和简洁文案 |
| 只发普通文字观点帖 | 一条自然英文改写，不为了交付而硬配图 |
| 转发并加一句简短评价 | 找相关原帖，准备一句 English Quote 评论，保留原生媒体 |
| 全新转发 | Quote 原帖，加新写的简短英文评论 |
| 全新发布，有视频 | standalone，直接上传新下载的视频，不换成 quote |
| 原帖只是一个没有视频的更早 teaser | 继续找承载目标视频的原帖，不机械选择最早时间 |
| 看过完整稿和视频后说“发布” | 直接发布该版本，不再要求确认同一内容 |
| 本次无需确认，直接发布 | 完成材料和事实检查后直接发布并核验 |
| 仅要求解释原文一句话 | 解释该句，不擅自扩展成发布任务 |
| 手机远程审阅 | 聊天内正文和图片，可访问的视频预览，不只给 localhost |
| 改为另一个模型 | 核对新模型数据并同步改图、文案、脚注，不能只改名字 |
| 上传后公开页面暂不可核验 | 报告已提交与核验未完成，先查现有帖子再决定是否重试 |
