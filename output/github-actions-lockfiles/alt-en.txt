Flowchart: Your code and workflow are unchanged, still using build@v2. Upstream moves the third-party action's v2 tag from commit A to B. Without a lockfile, v2 resolves to B and the next CI run may break. With an Actions lockfile, v2 stays readable but the next run still executes locked commit A. To upgrade, review B and approve the change, update the lock to B, then run B. Transitive action dependencies are covered; called reusable workflows use their own repository's lockfile. Locking does not certify safety. GitHub Actions public preview.
