# Reusable prompts for this workflow

These prompts describe the method implemented in this project. They are a reusable handoff, not a claim that each block was separately pasted into another model session.

## 1 Director brief

Create a 24-second 1920×1080 motion film at 60 fps about a packet taking an alternate route after a network link fails. Treat the animation as a routing metaphor, not a protocol simulation or measured failover result. Before writing code, create a six-shot table with frame ranges, main event, subject hierarchy, text, motion cause, sound cue and acceptance criteria. Keep one gold subject continuous throughout the story. Use LeoGuoLabs Light v1: ivory #FDFBF7, forest green #1A4A3A, muted green #426454, sparse gold, Geist sans serif, generous margins. No cards, glows, gradients, shadows, stock icons, or generic transition montage. You may choose routine implementation details and proceed through rendering and review.

## 2 Timeline and motion

Use Remotion with React and SVG. Put frame numbers, FPS, BPM, shot ranges and named events in a single JSON file. Use 120 BPM and 60 fps. Every visual must be a deterministic function of frame. Use a persistent hero, continuous positions, cubic Bézier routes, speed-dependent area-preserving deformation, and localized damped cable motion. Stagger related layers by a few frames. Do not apply the same easing to all objects or shake the entire frame. Keep the destination fixed during the routing sequence.

## 3 Sound

Generate an original 48 kHz stereo score locally in Python. Use restrained plucks, a sparse pulse and distinct event sounds. Read the same event JSON used by the animation. Give the connection break room in the mix, start sweeps slightly ahead of their visual culmination, and leave a natural decay at the ending. Save the WAV, event sample positions and audio measurement report. No external song or cloned voice.

## 4 Review before export

Render representative frames plus samples around the break and arrival. Inspect stacking order, actual contrast, safe margins, text collisions, endpoint continuity, and deformation. Preserve failed samples and write the concrete defect and fix to an iteration log. Check all subject positions numerically. Then render the full MP4, decode the entire file, inspect the streams and audio, and verify playback and seeking in a real player. Do not equate a successful export command with finished visual QA.

## 5 Explain the actual experiment

Write one English making-of article using only the work actually performed. Explain the brief, shot map, timing data, motion formulas, sound design, failed first pass, corrections, rendering, review, and reproducibility. Include useful commands and a reusable starting prompt. Keep project logs and source attribution in research files. Do not invent rendering costs, model comparisons, subjective audio audition, or a claim that the user manually performed the agent's checks.
