M5 Max 128GB — Qwen3.6-27B Q8_0 long-context Metal benchmark

Adding a bare-metal Apple M5 Max result, focusing on prompt processing and token generation performance as context depth increases.

Hardware

  • Apple M5 Max
  • 128 GB unified memory
  • Metal backend
  • recommendedMaxWorkingSetSize: ~115.4 GB

Model

  • Qwen3.6-27B
  • Q8_0 GGUF
  • 26.62 GiB
  • 26.90B parameters

Note: llama-bench reports the model as qwen35 27B Q8_0, apparently from the GGUF metadata. The actual model tested is Qwen3.6-27B Q8_0.

Configuration

  • Backend: BLAS + Metal
  • GPU layers: 99
  • Threads: 6
  • Flash Attention: enabled
  • K cache: Q8_0
  • V cache: Q8_0
  • Repetitions: 3
  • Prompt test: 512 tokens
  • Generation test: 256 tokens

Command

./llama-bench -m ./Qwen3.6-27B-Q8_0.gguf -ngl 99 -fa on -ctk q8_0 -ctv q8_0 -p 512 -n 256 -d 0,8192,16384,32768,65536,98304,131072,196608,262144 -r 3

Context scaling

TG drops from 17.46 t/s at depth 0 to:

  • 14.70 t/s at 8K
  • 13.69 t/s at 16K
  • 9.51 t/s at 32K
  • 8.24 t/s at 64K
  • 6.12 t/s at 128K
  • 4.27 t/s at 256K

There is a particularly noticeable drop between 16K and 32K.

PP512 also decreases substantially with context depth, from about 799 t/s at depth 0 to 27 t/s at 256K.

The model fits comfortably within unified memory, so I am curious how much of this long-context degradation is expected from attention/KV-cache bandwidth, and how much may be specific to the current Metal implementation or this Qwen architecture.

It would be interesting to compare this against other M5 Max results, especially with different KV cache types or recent llama.cpp builds.
