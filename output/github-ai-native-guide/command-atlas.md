# Git command atlas for AI-native work

The prompt describes the result. The diagram explains the operation the agent chooses. These labels explain command behavior; they are not a sequence to paste into a terminal. Commands that require arguments are intentionally abbreviated.

| Goal | Mechanisms and meaning | Prompts | Diagram |
|---|---|---|---|
| Carry intent through to evidence | Inspect → act → observe → report. A proposed action does not prove an executed result. | 01, 02, 28 | [02 — Agent loop](images/02-intent-loop.png) |
| Locate the work | Working files → index → local history → remote → PR → live page. Each operation changes a different layer. | 02 | [03 — State map](images/03-state-map.png) |
| Prepare tools, identity, and access | `git --version` reads the installed version. `git config` reads/changes settings; `--global` broadens their scope. `gh auth status/login`, `ssh-keygen`, and `ssh -T` concern service access, which is separate from commit identity. | 03 | [04 — Setup](images/04-setup.png) |
| Begin a local repository | `git init -b main` creates repository metadata and selects the initial branch name. It does not make the first commit or upload files. | 07 | [04 — Setup](images/04-setup.png) |
| Inspect state, history, and identity | `git status` / `--short` summarize tracked, staged, and untracked paths. `git log` / `--oneline` follow history. `git show` inspects a commit or object. `git blame` traces a line's relevant change. `git rev-parse HEAD` identifies the current commit. | 01, 02, 06, 11 | [05 — Inspection](images/05-inspection.png) |
| Give the change its own workspace | `git switch -c` creates/selects a branch. `git switch` changes the checkout; some uncommitted edits can travel with it. `git worktree add` provides separate working files and an index linked to shared repository history. | 09 | [06 — Branches](images/06-branches.png) |
| Select and record an exact snapshot | `git add` copies selected content into the index. `git diff` compares tracked working content with the index. `git diff --staged` compares the index with HEAD in the normal committed-repository case. `git commit` records the index and advances the current branch in the attached-branch case. | 10, 11 | [07 — Staging](images/07-staging.png) |
| Check local behavior | A local checker examines files; an HTTP preview and connected browser expose observed page behavior. Neither operation creates a commit or establishes a public deployment. | 11, 12 | [08 — Validation](images/08-validation.png) |
| Obtain and share history | `git clone` copies remote history locally and normally checks out files. `git remote add` names a destination; `git remote -v` displays destinations. `git fetch` downloads objects and updates configured remote-tracking references without integrating the current branch. `git push` requests remote reference updates; `-u` also records tracking for the successfully pushed/up-to-date branch. A GitHub fork and PR have their own repository/base/head relationships. | 08, 13, 14, 17 | [09 — Remotes](images/09-remotes.png) |
| Integrate the intended base | `git merge` can fast-forward or join divergent histories. `git merge --ff-only` refuses divergence. `git rebase` replays work with new commit identities. `git merge --abort` attempts to reconstruct the pre-merge state, most clearly when integration began clean. | 16, 17 | [10 — Integration](images/10-integration.png) |
| Deliver the reviewed result | Push → PR → checks/review → merge → deployment → browser. A branch, reviewed revision, hosted artifact, and working page each require their own evidence. | 13, 15, 18–20 | [11 — Delivery](images/11-delivery.png) |
| Recover the intended state | `git restore --staged` normally restores the index from HEAD while preserving working edits. `git stash push -u` saves tracked/untracked work but excludes ignored files; `git stash list` inspects entries and `git stash apply` restores work while retaining the entry. `git revert` appends an inverse commit. `git restore` replaces selected content from a chosen source. `git reset --hard` resets HEAD/index/working state and can discard local content. | 21 | [12 — Recovery](images/12-recovery.png) |
