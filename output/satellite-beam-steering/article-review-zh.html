用 Codex 制作视频的一套可复用流程

从导演 Brief 到成片验证：用一段 36 秒卫星短片说明六步流程，并将方法提炼为独立 Skill。

中文审查稿，对应英文文章 article.md，供核对内容与表达。

用 Codex 制作视频时，可以把工作分成六步：导演 Brief、分镜、共享时间线、运动与声音、检查修正、成片验证。这样更容易控制制作过程，也方便修改。

我用下面这套六步流程制作了《Steering without turning》（《阵面不转，波束转向》），一段 36 秒的卫星科普短片。镜头从完整卫星进入天线阵列，展示相对相位如何改变波束方向，再回到指向地面终端的例子。成片只是这套流程的一次应用。同样的决策顺序，也可以用于产品演示、科学讲解或简短的视觉故事。

1. 写一份导演 Brief

先定义观众，以及他们看完后应该理解或感受到的那一件事，再明确内容范围、视觉方向和交付要求。给 Codex 足够的信息，让它的各项选择都服务于同一个目标。

一份有用的 Brief 应回答五个问题：

  • 谁会看这段视频，可以假定他们已经知道什么？
  • 看完之后，希望他们记住哪一个核心观点或动作？
  • 哪些事实或事件必须出现，哪些内容不在这次的范围内？
  • 画面、字体、运动和声音应该给人什么感觉？
  • 需要交付什么：时长、画幅比例、分辨率、语言、音频、可编辑源码，以及审查文件？

卫星样片的目标，是解释当天线面板相对于卫星保持固定时，电子指向如何工作。链路预算、调度和切换不在这次范围内。视觉方向则是暖象牙白、森林绿、少量金色，以及清晰的无衬线标签。

Brief 应足够简短，方便在修改时随时查阅。当某个效果干扰了核心表达，它就能帮助你判断为什么应当删掉这个效果。

2. 把 Brief 转成分镜表

为每个镜头安排一项表达任务。明确它的主体、景别与构图、动作、文字、转场方式，以及观众应该带入下一个镜头的信息。镜头数量和时长应围绕这些任务安排。

下面是已完成样片使用的分镜表：

时间镜头表达任务
0–6 秒完整卫星找到平面天线的位置
6–12 秒阵面近景识别重复排列的辐射阵元
12–18 秒分离后的结构层展示经过简化的馈电结构
18–24 秒相位曲线与阵列因子将相对相位与波束方向联系起来
24–30 秒卫星与固定地面终端展示为什么需要改变指向
30–36 秒回到完整卫星将工作机制重新放回系统中理解

每段六秒的等长安排只属于这段样片。其他主题可能需要一段较长的演示，再配上几个较短的衔接镜头。

转场应保留一种有用的联系，比如同一个物体、位置、方向或因果关系。例如，阵面近景保留了面板的朝向和重复贴片，让观众认得相机进入了哪个部位。

先确定镜头需要什么，再选择渲染工具。本项目用 Three.js 和 React Three Fiber 处理几何体与相机，用 Remotion 组织按帧控制的画面，用 HTML/SVG 呈现标签和图形。Remotion 的 Three.js 集成支持这种组合。换一份分镜表，也可能需要实拍素材、平面图形或其他渲染工具。

3. 建立共享时间线

给重要动作设置有名称的事件和明确的帧号，让相机运动、物体动作、文字与声音都可以引用同一份安排。构建可复用实现时，应把时间定义集中到唯一的权威位置；各个脚本读取或接收这份定义，避免分别维护自己的副本。

下面这段精简表示，对应卫星样片实际使用的时间安排：

const fps = 60;
const totalFrames = 2160;
const shotStarts = [0, 360, 720, 1080, 1440, 1800];
const events = {
  phaseScene: 1080, // 18 秒：引入工作机制
  sweepStart: 1140, // 19 秒：开始改变角度
  sweepEnd: 1320,   // 22 秒：达到 30 度
  tracking: 1440,   // 24 秒：结束 30 度保持，进入跟踪镜头
};

进入镜头和开始动作，是两个不同的时刻。相位镜头先留一秒，让观众看清画面；接着用三秒改变角度，最后保持结果两秒。

对于程序生成的动画，应直接根据请求的帧号推导状态。本例中的相机位置、层间分离、相位和指向，都是镜头局部时间的函数。因此，单独渲染某一帧不需要先播放之前的全部帧。这让局部修改和重复检查更容易完成。

4. 围绕事件制作运动与声音

决定什么先动、什么随后发生、在哪里加速，以及在哪里收稳。动作前的预备或短暂停留，都应帮助观众看懂动作。在让视线追踪另一件事之前，先给标签足够的阅读时间。

讲解机制的镜头中，画面和数值读数应由同一个底层状态驱动。样片中的相位曲线、波束角标签、波前朝向和阵列因子，都跟随同一个扫描角变化。演示采用理想的八阵元阵列，阵元间距为半波长，所有阵元始终同时工作。模型保留了旁瓣，也明确了适用边界。Analog Devices 的相控阵教程介绍了相关几何原理。

声音也需要明确的主次。音乐负责连贯感，有选择地使用事件音来强调重点。确定声音是与动作同时开始、提前引入动作，还是在动作结束后收束。仅仅共用一个时间戳，还没有考虑声音的起音和衰减过程。

样片使用 Python/NumPy 合成的原创配乐，节拍为 100 BPM，并在镜头切换附近安排简短声音提示。这个速度只是本例的选择。节拍网格可以帮助组织重点，但不意味着每个物体都必须在每一拍上运动。样片没有旁白，因此静音观看时，字幕和画面承担解释任务。

5. 检查、定位问题并修改

在完整导出视频之前，先渲染有代表性的画面。检查每个镜头的开头、最能表达含义的时刻，以及结束位置。在快速运动、重叠、转场和状态变化附近，增加相邻帧采样。用全尺寸图片检查细节，用缩略图总览检查整段顺序。

检查应落在具体问题上：能否认出主体，标签是否指向正确对象，文字在目标观看尺寸下是否可读，画面结果是否与底层状态一致？

卫星样片的第一批静帧中，部分贴片被埋进了带倒角的面板。把贴片几何体向前移动，解决了这个问题。一个微距镜头还让太阳翼与标题和侧边说明重叠；围绕阵面重新构图后，恢复了必要的间距。这些都能直接执行，比笼统地要求“提高质量”更有用。

记录问题、修改内容，以及用于验证的帧。然后重新查看修改过的镜头和前后相邻镜头。数值检查可以补充视觉审查：本例核对阵列因子峰值是否对应设定角度，以及指向线是否经过固定终端。这类检查证明的是内部一致性，并不等于验证了完整的无线系统。

6. 验证最终交付视频

检查实际编码完成的文件，确认时长、尺寸、帧数、编码格式、色彩元数据和音频流。完整解码文件，以发现抽样画面之外的错误。对这个文件测量响度，再在实际播放器中带声音播放并测试跳转。

卫星样片的最终文件为 1920 × 1080、60 fps：36.000 秒内完整解码得到 2,160 帧。H.264 视频采用 4:2:0 采样和有限范围 BT.709 色彩，音频为 48 kHz 立体声 AAC。最终 MP4 的综合响度实测为 −18.00 LUFS，真峰值为 −2.86 dBTP。在本地浏览器中，视频播放至结束，没有报告媒体错误；审片控件也在连续的第 1,320 帧和第 1,321 帧完成了检查。

这些结果描述的是这一个文件，并不意味着所有项目都应使用同一种帧率、响度或编码格式。根据视频的目标用途设定交付要求，并保留足够证据，区分“要求采用的设置”和“最终测得的结果”。

将视频连同 Brief、分镜表、时间定义、可编辑源码和简短审查记录一起交付，下一次修改就有了可靠的起点。

配套的 $video-director Skill 将这六步封装为一套独立、可用于不同主题的工作流程。它是在完成制作之后提炼出来的，卫星短片是其中的实际案例。可复用的是从明确 Brief 到验证成片的过程，以及让每一项创意决策都有一个可以检查和修改的落点。
