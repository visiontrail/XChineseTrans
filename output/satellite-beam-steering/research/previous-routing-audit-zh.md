# 上一版路由短片：简短对照

此文件仅对照本项目上一版《A route around failure》，**不是用户后来指定的 Andy 参考片审片报告**。

- 文件：`../../codex-motion-routing/route-around-failure.mp4`。
- ffprobe 与完整解码均确认：1920×1080、60 fps、24.000 秒、1440 帧；H.264 + AAC 48 kHz 双声道。
- 实际技术：Remotion 4.0.530 / React / TypeScript / SVG，按帧确定的位置和缓动；Python + NumPy 生成配乐和事件音；FFmpeg 编码。没有真实三维几何、相机、材质或光照。
- 审查范围：全部 1440 帧自动解码与变化测量；人工查看 12 帧联系表（F90、330、478、480、486、498、720、750、810、870、1110、1260）。**不声称人工逐帧看完 1440 帧。**

## 已观察到的问题

1. **主体长期停住。** 黄包 F420（7.0s）到 F750（12.5s）保持在路由器，共 5.5 秒。断路 F480（8.0s）到备选路径开始 F720（12.0s）间隔 4 秒，画面只靠标题、轻微环形提示和闪动维持。这使“发现故障→选路→发送”的因果变成慢速文字解释。
2. **缺少镜头层级。** F330、486、810、1110 均是相同远景拓扑，观众必须追踪一个小圆点。线条与节点在手机宽度下很细，故障与改路的视觉显著性有限。
3. **弹性造型比机制更明显。** F486 的断线像绳索回弹，F498 的叉号给出了结果，但没有展示检测故障、更新路径或转发选择，适合“routing metaphor”，不能当技术机制演示。
4. **视觉语言变化有限。** 开尾均是文字左置、装饰轨道右置；中段基本是同一平面 SVG。F1260 的标题页与 F90 类似，缺少从最终结果回看技术机制的闭环。

## 可复用与需改变的部分

保留共享帧时间线、可复现渲染、英文排版、事件声效和全片解码验证。新卫星样片应增加真实三维几何与相机距离变化，并把一个可解释的控制变量连接到画面结果，例如“阵列相位差→波前倾斜→主波束转向→地面覆盖位置变化”。不靠增加装饰性运动来代替机制。
